# Feature inventory and comparison

Evidence levels: **source** means implementation or settings declarations exist in the checked-out tag; **payload** means a file, string or decoded resource is present. Neither means runtime success. The tagged sources have not been proven byte-equivalent to the supplied binaries. The inventory below is a functional grouping; exhaustive behavior cannot be established without source execution and target-app analysis. Current status is in `UNIFIED-v5-STATUS.md`; v5 behavior remains **NOT RUNTIME TESTED**.

`source/source-files.json` indexes 596 implementation/header files across both repositories. `source/hook-declarations.json` indexes 325 textual hook declarations. `source/settings-literals.json` records 249 occurrences of candidate preference/identifier literals with source lines. `binary/feature-candidates.json` retains 768 binary/localization candidates, including messages that are not features. These counts must not be reported as numbers of working features. Dynamic/generated preferences, selectors, runtime conditions, helper swizzles and external services still require manual tracing.

The provider names, subfeatures and settings above are source/resource evidence. Live website descriptions may cover newer versions and are deliberately not treated as proof of the supplied release's functionality. Server-sided downloads and very high quality audio are explicitly described by Eevee's supplied localization as unavailable through the tweak; their UI labels do not establish those capabilities.

## Interfaces and runtime conditions

Chroma organizes Mod Settings around its native/redesigned mode. Native and redesigned implementations intentionally use separate namespaces and mode gates. A unified implementation must not collapse their keys merely because the labels match. Its source guidance requires runtime class/selector evidence before hooking Spotify and notes constraints for navigation controllers, Encore stack visibility and display-link refresh behavior.

Eevee's root settings group Listening (patching/lyrics/SponsorBlock), Looks (appearance/customization/icon) and Advanced (Spotify features/flags/experiments/miscellaneous). It also exposes log/reset/support actions. `Tweak.x.swift` selects v91 for a version containing 9.1, with class/selector checks before activating several groups. Its 9.1.x path returns before some older-version option activations: a settings row's existence does not establish that its hook runs on 9.1.90. See `source/activation-evidence.json` for candidate branch locations and inspect the original source around them.

## Concrete conflict evidence

1. Chroma `Native/Navbar/TabBarHooks.x:35` and Eevee `LiquidGlass/GlassTabBar.x.swift:296` target `_TtC23NavigationUI_TabBarImpl10TabBarView` and implement `layoutSubviews`. Both call the original before changing/composing the bar. Two independently maintained replacement bars can duplicate state and interactions.
2. Chroma `Shared/LyricsSources/LyricsHook.x:520` hooks SPTDataLoaderService delegate response/data/completion callbacks. Eevee's DataLoaderService hook changes the same callback flow. Both collect or replace bytes; cascading them may break per-task buffering and completion assumptions.
3. Chroma also hooks the mangled HttpClientURLSession name while Eevee uses its Swift-qualified runtime name. These represent a likely alias collision missed by simple literal equality. Runtime class identity must be verified against Spotify.
4. Shared-target candidates include settings-list insertion, Home gradient/section views, player backgrounds, lyrics views, mini player and generic UIView-related hooks. `source/shared-hook-targets.csv` contains 115 declaration pairs with source locations. Some pairs are mutually exclusive modes or affect different selectors, so the CSV is a review queue, not 115 proven bugs.

No coexistence guarantee follows from source presence, a unique filename, disjoint class names or this lexical index. A runtime-owned class/selector/type-encoding map is still required.
